# Build step 5: Run several Claude sessions — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Developer runs more than one Claude session on the Folder and can tell their work apart:
- new sessions open as Claude 2, Claude 3 and so on;
- each Change names the session that made it;
- two sessions changing the same file both show an overlap mark;
- closing a working session asks first;
- a renamed session's new name shows everywhere.

**Architecture:** Claude starts already route hooks, status, notifications and review by their own start key, so most of the plumbing exists.
- **Main:** the review keeps one Folder-wide touch log (path, tab, sequence number) instead of one per session. Each Change carries the tabs of the sessions that made it, and overlaps between open sessions are pushed to the renderer. A new IPC call ends a Claude tab's program.
- **Renderer:** adds the `+` action, the close action with its question, in-place renaming, the overlap mark, and a Changes pane that follows the Claude tab focused last.

**Tech Stack:** As in build step 4 (Electron 45.4.1, electron-vite 6.0.0, React 19, TypeScript 7, dockview-react 8.9.1, @base-ui/react 1.9.0 for the dialog, zustand 5, Vitest 5, @playwright/test 1.65). No new dependencies.

## Global Constraints

- Linux first. Dev and test runs start Electron with `--no-sandbox`. Windows keep `contextIsolation: true`, `sandbox: true` and `nodeIntegration: false`, and the renderer reaches main only through `window.blueprint`.
- Claude tabs are `claude-<n>`. `claude-1` is titled `Claude`, and `claude-<n>` for n ≥ 2 starts titled `Claude <n>`. A new tab's `n` is one more than the highest `n` among open Claude tabs and those opened earlier in this run, so a closed session's number is never reused while Blueprint runs (amended in Task 2: a reused id would put a closed session's Changes under the new session's name).
- The `+` header action has the accessible name `New Claude session`. It shows in every group that holds a Claude tab, and adds the new tab to that group, active and focused.
- Only Claude tabs have a close action (button and middle-click), and never the last open one.
- Closing an Idle session closes it at once. A Working or Needs-you session first opens Blueprint's own dialog, never `window.confirm`:
  - heading: `Close <name>?`;
  - body: `It is still working.` (Working) or `It is waiting for your answer.` (Needs you);
  - buttons: `Close session` and `Keep it`.
- Closing ends the tab's program and forgets its start key and status. A closed session's touches stay in the review under its last name.
- Each Changes row's mark has an accessible name:
  - `●` with the names of the sessions that made it, joined by `, `;
  - or `○` with `Changed outside Claude`.

  The Changes header names the session it shows.
- The overlap mark sits on the tab, coloured `--bp-del`. It has `role="img"`, the accessible name `Overlap with <names joined by ", ">`, and the `title` `Also changed by <names>: <paths joined by ", ">`.
- Renaming:
  - double-click a Claude tab's title;
  - Enter or blur keeps the trimmed new name, Escape keeps the old one, and an empty name keeps the old one;
  - the name is the dockview panel title, used by the tab, the window title, notifications, the Changes pane and the close dialog, and saved with the layout.
- A restored layout accepts any `claude-<n>` panel (`terminal`, kind `claude`). Unknown ids still give the default layout.
- Production code has no test-only branches beyond the existing e2e probe.
- Commit messages follow the repo's style (plain imperative sentence, no `feat:` prefix) and never carry Co-Authored-By or other attribution lines.
- Before finishing, `sh scripts/check_links_integrity.sh` prints only `check-done`, and `pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm e2e` passes.

## Review Focus

1. Closing the session the Changes pane shows. The pane switches to the Claude tab focused before it, or else the first open one, and never stays on the closed one. Test: Task 3.
2. Closing a session that is Working or Needs you, after confirming. Its name leaves the window title, no notification fires for it afterwards, and its program has exited. Test: Task 2.
3. Many sessions. Starting four more gives Claude 2 to 5. Closing Claude 3 and starting another gives Claude 6, not a second Claude 3. Test: Task 2.
4. A session that edited files and then closed. Its Changes stay tagged with its last name in another session's This session list. Test: Task 3.
5. A renamed session after reopening the Folder. The tab keeps the new name and starts a fresh session. Test: Task 4.

### Task 1: Tell each session's Changes apart in the review

**Files:**
- Modify: `src/main/review/attribution.ts`, `src/main/review/service.ts`, `src/shared/api.ts`, `src/main/index.ts` (pass a no-op `sendOverlaps` until Task 3); the renderer's uses of `byClaude` on `Change` (`src/renderer/src/review/ChangesPanel.tsx`, `store.test.ts`), changed only enough to compile and behave as before (`●` when `by` is not empty); every `setReviewView` caller (`ChangesPanel.tsx`, `watchReview` in `tests/e2e/launch.ts`) passes `tabId: null` until Task 3
- Test: `src/main/review/attribution.test.ts`, `src/main/review/service.test.ts`

**Interfaces:**
- Produces: `class TouchLog` with these methods:
  - `touch(path: string, tabId: string): void`, which records the path, the tab and the next sequence number;
  - `mark(): number`, the current sequence number, which a range starts from;
  - `by(path: string, since: number): string[]`, the tabs that touched the path after `since`, in first-touch order;
  - `overlaps(open: { tabId: string; since: number }[]): Overlap[]`, where two open sessions overlap on each path both touched after their own `since`.
- Produces: in `ReviewService`:
  - the shown session is the one whose tab is `view.tabId`. When that tab has no session, it falls back to the newest start, which is today's behaviour;
  - each session keeps the sequence `mark()` of its start and of its latest Developer prompt;
  - a Change's `by` is `log.by(path, rangeStart)`;
  - `endSession(tabId: string): void` drops the tab's session from the open sessions and from overlaps, but keeps its touches;
  - the constructor gains `sendOverlaps: (o: Overlap[]) => void`, which is called after every touch, `startSession` and `endSession` when the overlaps changed.
