# Build step 1: Claude and a shell in tiled panes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open a Folder in Blueprint and get a real Claude Code session and the Developer's shell side by side, in tabbed, resizable, draggable, zoomable panes, in the Blueprint look.

**Architecture:** An electron-vite app at the repo root, next to `entries/`. The main process owns the Folder and every pseudo-terminal (node-pty), and exposes them to a sandboxed renderer through one typed preload API (`window.blueprint`). The renderer lays out panes with dockview and draws each terminal with xterm.js (fit, ligatures, then WebGL with a DOM fallback). Slice test cases run as Playwright tests against the built app, with fake `claude` and shell programs that log what they receive.

**Tech Stack:** Electron 45.4.1, electron-vite 6.0.0, React 19, TypeScript 7, Tailwind CSS 4.3 (`@tailwindcss/vite`), shadcn/ui on Base UI, lucide-react, dockview-react 8.9.1, @xterm/xterm 6.0.0 with addon-fit 0.11.0, addon-ligatures 0.10.0 and addon-webgl 0.19.0, node-pty 1.1.0, zustand 5, Vitest 5, @playwright/test 1.65, pnpm 12.

## Global Constraints

- Linux first. Dev and test runs start Electron with `--no-sandbox`, because Ubuntu's AppArmor blocks Chromium's sandbox for unpackaged apps.
- Windows use `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`. The renderer reaches the main process only through `window.blueprint`.
- Claude Code is the real `claude` CLI under the Developer's own sign-in. No Agent SDK, no API key.
- Every pseudo-terminal's environment drops `CLAUDECODE` and `CLAUDE_CODE_ENTRYPOINT`, and sets `TERM=xterm-256color` and `COLORTERM=truecolor`.
- Claude sessions start with `claude --session-id <uuid>`. Hooks (`--settings`) and resume belong to later build steps.
- Look: the Blueprint Default scheme only, with tokens copied from `blueprint-default` in the prototype's `src/looks/themes.js`. Corner radius 0. Window chrome in Overpass (`@fontsource-variable/overpass`), pane text in Cascadia Code (`@fontsource-variable/cascadia-code`). Load the ligatures add-on before the WebGL add-on.
- UI copy uses the glossary's words: Folder, Pane, Tab, Claude session.
- Production code has no test-only branches, except the e2e probe in Task 5, which only exists when `BLUEPRINT_E2E=1`.
- Commit messages follow the repo's style (plain imperative sentence, no `feat:` prefix) and never carry Co-Authored-By or other attribution lines.
- Before finishing, `sh scripts/check_links_integrity.sh` prints only `check-done`.

## Review Focus

1. Blueprint is started with a PATH that lacks `~/.local/bin`, where the native installer puts `claude` (a desktop launcher does this). Claude Code should still start. Test: Task 3, `findExecutable` falls back to `$HOME/.local/bin`.
2. The Folder argument is relative, missing, or a file. A relative path resolves against the launch folder; a bad one shows the Open Folder screen with the reason. Test: Task 2, `resolveFolder` cases.
3. A terminal starts before its pane has a size, so fit proposes no dimensions or zero. node-pty must still get a valid size. Test: Task 4, size clamping.
4. Terminal keys such as Ctrl+W, Ctrl+R and Ctrl+V reach the program instead of an app menu that closes the window or reloads the page. Test: Task 7, Ctrl+W and Ctrl+R reach the fake Claude Code.
5. Closing Blueprint while sessions run leaves no orphaned `claude` or shell processes. Test: Task 6, the fake programs' processes are gone after quit.

Shared types, defined in Task 2 and Task 4 and used everywhere after:

```ts
// src/shared/api.ts
export type TerminalKind = 'claude' | 'shell'
export interface FolderState { folder: string | null; problem?: string }
export interface StartRequest { tabId: string; kind: TerminalKind; cols: number; rows: number }
export type StartFailure =
  | { reason: 'not-installed'; message: string; fix: string }
  | { reason: 'spawn-failed'; message: string }
export type StartResult = { ok: true; pid: number } | { ok: false; failure: StartFailure }
export interface ExitInfo { exitCode: number; signal?: number }
export interface BlueprintApi {
  e2e: boolean
  getFolder(): Promise<FolderState>
  pickFolder(): Promise<FolderState>
  startTerminal(req: StartRequest): Promise<StartResult>
  write(tabId: string, data: string): void
  resize(tabId: string, cols: number, rows: number): void
  onData(tabId: string, cb: (data: string) => void): () => void
  onExit(tabId: string, cb: (exit: ExitInfo) => void): () => void
  readClipboard(): Promise<string>
  writeClipboard(text: string): void
}
```

### Task 4: Run terminals in the main process

**Files:**
- Create: `src/main/terminal/manager.ts`

**Interfaces:**
- Consumes: `SpawnSpec`, `claudeSpec`, `shellSpec` from Task 3.
- Produces: `interface TerminalSink { data(tabId: string, data: string): void; exit(tabId: string, exit: ExitInfo): void }`.
- Produces: `class TerminalManager` with:
  - `constructor(sink: TerminalSink)`;
  - `start(tabId: string, spec: SpawnSpec, cols: number, rows: number): number` (returns the pid; kills a running terminal with the same tab id first);
  - `write(tabId: string, data: string): void`;
  - `resize(tabId: string, cols: number, rows: number): void`;
  - `kill(tabId: string): void`;
  - `killAll(): void`.

  Sizes are floored and clamped to at least 2 columns and 2 rows. Unknown tab ids are no-ops. Only the current terminal of a tab reports its exit.
- Produces: IPC.
  - `terminal:start` (invoke) builds the spec from the kind, using a new `crypto.randomUUID()` per Claude start. It returns `StartResult`: a `StartFailure` from the spec, or `{ reason: 'spawn-failed', message }` when node-pty throws.
  - `terminal:write`, `terminal:resize` (send). `terminal:data` and `terminal:exit` go from main to renderer through the sink.
  - `clipboard:read` (invoke) and `clipboard:write` (send) use Electron's `clipboard`.
  - The preload API's `onData` and `onExit` filter by tab id and return an unsubscribe function.
