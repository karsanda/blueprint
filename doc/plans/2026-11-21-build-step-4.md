# Build step 4: Remember the layout — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the Developer reopens a Folder, its panes come back as they left them, and the window comes back at the same size and place.

**Architecture:** One small JSON file per Folder in Blueprint's user data holds two things: the dockview layout and the window's bounds.
- The renderer sends `api.toJSON()` to main 500 ms after the last layout change, and on open loads it back with `api.fromJSON`. A broken or foreign file gives the default layout, and a missing default pane is added back.
- Main saves the window's bounds after a move or resize, and opens the window at them when they are still on screen.

**Tech Stack:** As in build step 3 (Electron 45.4.1, electron-vite 6.0.0, React 19, TypeScript 7, dockview-react 8.9.1, zustand 5, Vitest 5, @playwright/test 1.65). No new dependencies.

## Global Constraints

- Linux first. Dev and test runs start Electron with `--no-sandbox`. Windows keep `contextIsolation: true`, `sandbox: true` and `nodeIntegration: false`, and the renderer reaches main only through `window.blueprint`.
- The layout file is `<user data>/layouts/<first 16 hex digits of sha256(Folder path)>.json`. It is written whole to `<file>.tmp`, then renamed over the old one.
- Its content is `{ version: 1, folder, dockview?, window? }`. `dockview` is the value of `api.toJSON()`, and main treats it as opaque. `window` is `{ x, y, width, height, maximized }`, the normal bounds.
- The renderer saves 500 ms after the last `onDidLayoutChange`, and never while a group is maximized (zoomed).
- Main saves the window 500 ms after the last `move` or `resize`, and again on `close`.
- The window opens at its saved bounds when at least 100 × 100 px of them fall on one display's work area. Otherwise it opens at the default 1280 × 800. It is maximized again when it was maximized.
- The default panes are `claude-1` (terminal, Claude), `shell-1` (terminal, Shell), `changes` and `difference`. A saved layout naming any other panel, or lacking `claude-1`, gives the default layout. Terminal panels keep `renderer: 'always'`.
- Nothing is zoomed after a Folder opens.
- Production code has no test-only branches beyond the existing e2e probe. e2e runs keep their user data in the temp home (`XDG_CONFIG_HOME`, as today).
- Commit messages follow the repo's style (plain imperative sentence, no `feat:` prefix) and never carry Co-Authored-By or other attribution lines.
- Before finishing, `sh scripts/check_links_integrity.sh` prints only `check-done`, and `pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm e2e` passes.

## Review Focus

1. A broken or foreign layout file: broken JSON, an unknown panel, a newer `version`. Blueprint opens the default layout and does not crash. Tests: Task 1 (`readLayout`) and Task 3 (e2e).
2. A layout saved before the review panes existed, with only Claude and Shell. Changes and Difference are added back where the default puts them, and the saved arrangement of the other panes stays. Test: Task 3.
3. Quitting while a pane is zoomed. The Folder reopens with its last unzoomed layout and nothing zoomed. Test: Task 3.
4. Saved window bounds on a display that is gone. The window opens at the default size, on screen. Test: Task 1 (`initialWindow`).
5. Two Folders. Each keeps its own layout, and a Folder never opened before gets the default. Test: Task 3.

Shared type, added to `src/shared/api.ts` in Task 1:

```ts
/** A window's normal (unmaximized) bounds, and whether it was maximized. */
export interface WindowBounds {
  x: number
  y: number
  width: number
  height: number
  maximized: boolean
}
```

### Task 1: Keep each Folder's layout in a file

**Files:**
- Create: `src/main/layout/store.ts`
- Modify: `src/shared/api.ts` (`WindowBounds`)
- Test: `src/main/layout/store.test.ts`

**Interfaces:**
- Produces: `interface SavedLayout { version: 1; folder: string; dockview?: unknown; window?: WindowBounds }`.
- Produces: `layoutFile(userData: string, folder: string): string`, which gives `<userData>/layouts/<first 16 hex of sha256(folder)>.json`.
- Produces: `readLayout(file: string): SavedLayout | null`. It returns `null` when the file is missing or not JSON, is not an object, or its `version` is not `1`. A `window` whose four numbers aren't finite numbers is dropped, and the rest kept.
- Produces: `writeLayout(file: string, folder: string, patch: { dockview?: unknown; window?: WindowBounds }): void`. It merges the patch into what `readLayout` finds (or into `{ version: 1, folder }`), creates the dir, and writes `<file>.tmp` then renames it. It is synchronous.
- Produces: `initialWindow(saved: WindowBounds | undefined, workAreas: { x: number; y: number; width: number; height: number }[]): { bounds?: { x: number; y: number; width: number; height: number }; maximized: boolean }`. It gives the saved bounds when at least 100 × 100 px of them overlap one work area, and no bounds otherwise. `maximized` comes from `saved` either way.

- [ ] **Step 1: Write the failing tests.**
  - `'layoutFile puts each Folder in its own file under layouts'`:
    - `layoutFile('/u', '/home/d/proj')` matches `/^\/u\/layouts\/[0-9a-f]{16}\.json$/`;
    - another Folder gives another file;
    - the same Folder gives the same file.
  - `'writeLayout keeps the dockview and window parts apart'`: write `{ dockview: { a: 1 } }`, then `{ window: bounds }`. `readLayout` gives `{ version: 1, folder, dockview: { a: 1 }, window: bounds }`, and no `.tmp` file is left behind.
  - `'readLayout ignores a file it cannot trust'`: `null` for a missing file, `'{'`, `'[]'`, `'"x"'` and `{ "version": 2 }`.
  - `'readLayout drops a window with broken numbers'`: `{ version: 1, folder, dockview: {}, window: { x: 'a', y: 0, width: 10, height: 10, maximized: false } }` reads with `window` undefined and `dockview` kept.
  - `'initialWindow keeps bounds that are on screen'`: saved `{ x: 100, y: 80, width: 1000, height: 700, maximized: false }` with work area `{ x: 0, y: 0, width: 1920, height: 1080 }` gives those bounds.
  - `'initialWindow drops bounds on a display that is gone'` (Review Focus 4): saved at `x: 3000` with the same single work area gives `bounds` undefined. A window overlapping the work area by only 50 px also gives undefined.
  - `'initialWindow keeps maximized'`: `maximized: true` comes through, with or without bounds.

### Task 2: Bring the window back at its size and place, and carry the layout over IPC

**Files:**
- Modify: `src/main/index.ts`, `src/main/ipc.ts`, `src/preload/index.ts`, `src/shared/api.ts`, `tests/e2e/launch.ts`
- Test: `tests/e2e/layout.spec.ts`

**Interfaces:**
- Consumes: `layoutFile`, `readLayout`, `writeLayout`, `initialWindow` (Task 1).
- Produces: in `index.ts`:
  - `createWindow` takes the result of `initialWindow(readLayout(file)?.window, screen.getAllDisplays().map((d) => d.workArea))` for the startup Folder. It uses `bounds` when given, and calls `win.maximize()` before `show` when `maximized`.
  - The window's `move` and `resize` save `{ ...win.getNormalBounds(), maximized: win.isMaximized() }` 500 ms after the last event, and `close` saves at once. The file comes from the Folder open at save time, so a picked Folder saves to its own file. Nothing is saved while no Folder is open.
- Produces: IPC in `ipc.ts`:
  - `layout:get` (invoke) returns `readLayout(file)?.dockview ?? null` for the open Folder, or `null` when none is open;
  - `layout:save` (renderer to main, the dockview JSON) calls `writeLayout(file, folder, { dockview })`.
- Produces: `BlueprintApi.getLayout(): Promise<unknown>` and `BlueprintApi.saveLayout(layout: unknown): void`.
- Produces: `LaunchOptions.home?: string` (reuse that home, and with it the user data) and `Launched.home: string`.

### Task 3: Restore the panes when the Folder opens again

**Files:**
- Create: `src/renderer/src/workspace/persist.ts`
- Modify: `src/renderer/src/workspace/defaultLayout.ts`, `src/renderer/src/workspace/Workspace.tsx`, `entries/usecase/blueprint/arrange_my_panes.md`, `entries/domain/workspace/notes.md`
- Test: `tests/e2e/layout.spec.ts`

**Interfaces:**
- Consumes: `getLayout`, `saveLayout` (Task 2).
- Produces: `addDefaultPanels(api: DockviewApi): void` adds each default pane that is missing, where the default layout puts it:
  - `changes` left of `claude-1` (`initialWidth: 250`);
  - `shell-1` below `claude-1`;
  - `difference` right of `claude-1`.

  When it had to add `claude-1` (a fresh layout), it makes `claude-1` active as today.
- Produces: `restoreLayout(api: DockviewApi, saved: unknown): boolean`. It returns `false` after `api.clear()` in three cases:
  - `api.fromJSON(saved)` throws;
  - the result lacks `claude-1`;
  - the result has a panel whose id isn't one of the four default ids.

  It exits a maximized group if one came back. Otherwise it returns `true`.
- Produces: `installLayoutSaving(api: DockviewApi): () => void`. On `api.onDidLayoutChange` it debounces 500 ms. It skips while `api.hasMaximizedGroup()`, and otherwise calls `window.blueprint.saveLayout(api.toJSON())`. It returns a disposer.
- Produces: `Workspace`'s `onReady`:
  1. awaits `getLayout()`;
  2. calls `restoreLayout` when there is one;
  3. always calls `addDefaultPanels`, then `installLayoutSaving`;
  4. `installTitle` and `installNotifications` stay as they are.
