# Build step 3: Review what Claude changed — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Developer sees which files changed since their last prompt, or since the session started. Each file is marked as Claude's or changed outside Claude, and picking one shows its difference, with revision clouds around Claude's changes.

**Architecture:** The main process owns the review.
- A `SnapshotStore` records the Folder as a git tree, with Blueprint's own index file and object store, so the Developer's repository is never written.
- A `ReviewService` takes snapshots at the moments the notes list:
  - when Claude starts;
  - on the Developer's prompt and before each of Claude's shell commands, holding the hook's reply until the snapshot is written;
  - after tools and turns, when the window comes to the front, and every 2 seconds while the Changes pane is visible.
- It records which paths Claude touched, and pushes a `ReviewState` to the renderer.
- The renderer draws two new panes in the default layout. Changes lists the files and switches range. Difference renders the unified diff with Shiki highlighting and revision clouds.

**Tech Stack:** As in build step 2 (Electron 45.4.1, electron-vite 6.0.0, React 19, TypeScript 7, Tailwind CSS 4.3, dockview-react 8.9.1, @xterm/xterm 6.0.0, node-pty 1.1.0, zustand 5, Vitest 5, @playwright/test 1.65). Git is run as the `git` program. New: `shiki` 4.6.0.

## Global Constraints

- Linux first. Dev and test runs start Electron with `--no-sandbox`. Windows keep `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, and the renderer reaches main only through `window.blueprint`.
- Claude Code 2.1.330 is the reference version. Blueprint adds its hooks with `--settings <file>` and never edits the Developer's settings.
- Hooks are HTTP hooks, and the listener answers `204` with no body:
  - `UserPromptSubmit` and `PreToolUse` (matcher `Bash`) have `timeout: 10`;
  - `PermissionRequest` (matcher `*`), `PostToolUse` (matcher `*`), `PostToolUseFailure` (matcher `Bash`), `Notification` and `Stop` have `timeout: 2`.
  - Amended in Task 4: a failing `Bash` command fires `PostToolUseFailure`, not `PostToolUse` (checked with Claude Code 2.1.330). Review treats it like `PostToolUse` for `Bash`; status ignores it.
- Blueprint never writes into the Developer's repository, index or files. Every git command it runs has these three variables set:
  - `GIT_INDEX_FILE=<store>/index`
  - `GIT_OBJECT_DIRECTORY=<store>/objects`
  - `GIT_ALTERNATE_OBJECT_DIRECTORIES=<the output of git rev-parse --path-format=absolute --git-path objects>`
- `<store>` is `<run dir>/<first 16 hex digits of sha256(Folder path)>`. The run dir is `<user data>/review-<pid>-<random>`, made `0700` at start and removed on quit.
- Git commands, run in the Folder:
  - snapshot: `git add -A -- .`, then `git write-tree`;
  - list: `git diff --no-renames --relative -z --name-status <a> <b>` and `git diff --no-renames --relative -z --numstat <a> <b>`;
  - one file: `git diff --no-color --no-ext-diff --no-textconv --no-renames --relative <a> <b> -- <path>`.
- Claude Code's own prompts begin with `<task-notification>` or `<agent-message`. They do not start a turn.
- The refresh poll runs every 2000 ms while the Changes pane is visible.
- UI copy:
  - tab titles: `Changes`, `Difference`;
  - range buttons: `This turn`, `This session`;
  - row marks: `●` with accessible name `Claude`, and `○` with accessible name `Changed outside Claude`;
  - Folder not in a repository: `Review needs Git. This Folder is not a Git repository.`;
  - Git missing: `Review needs Git, and Git is not installed.`;
  - no Claude start yet: `Changes show here once Claude starts.`;
  - This turn before the first prompt: `No prompt yet. Changes show here after your first prompt.`;
  - empty list: `No changes yet.`;
  - nothing picked: `Pick a change to see its difference.`;
  - binary file: `Binary file.`
- Colors come from the tokens:
  - the `●` mark and the revision cloud use `--bp-agent` (`#ffd166`, `rgb(255, 209, 102)`), and the cloud is a 1.6px stroke;
  - the `○` mark uses `--bp-muted`;
  - added rows are tinted with `--bp-add` and removed rows with `--bp-del`.
- `shiki` is pinned at exactly `4.6.0`, as a devDependency like the other renderer packages. It uses its JavaScript regex engine, because the renderer's CSP allows no WebAssembly.
- Production code has no test-only branches beyond the existing e2e probe. Tests reach main through `window.blueprint` and `app.evaluate`.
- Commit messages follow the repo's style (plain imperative sentence, no `feat:` prefix) and never carry Co-Authored-By or other attribution lines.
- Before finishing, `sh scripts/check_links_integrity.sh` prints only `check-done`, and `pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm e2e` passes.

## Review Focus

1. Claude changes a file through a shell command or a subagent, not its edit tools. It counts as Claude's. Tests: Task 4 (`ReviewService`), Task 5 (fake key `b`).
2. Claude Code's own prompt arrives mid-turn, when a background command ends or a subagent hands back. This turn keeps the Developer's prompt as its base. Tests: Task 2, Task 4, Task 5 (fake key `g`).
3. Three kinds of awkward Folder. Paths stay right, relative to the Folder, and no file outside it shows:
   - the Folder is a subfolder of a repository;
   - paths have spaces or non-ASCII letters;
   - the Developer's git config sets an external diff tool or `diff.noprefix`.

   Test: Task 1.
4. A new, deleted or binary file, and a picked file that changes again. These are Alternative Flows 3 and 4, which no slice test case covers. A new or deleted file shows whole, a binary file says `Binary file.`, and the difference follows the file. Test: Task 7.
5. `/clear` and Restart mid-session. This session survives `/clear`. Restart starts it fresh, and hooks from the old start change nothing. Tests: Task 4, Task 6 (fake key `c`).

Shared types, added to `src/shared/api.ts` in Task 1 and used everywhere after:

```ts
export type ReviewRange = 'turn' | 'session'
/** The Changes pane's range, and whether the Developer can see the pane. */
export interface ReviewView {
  range: ReviewRange
  visible: boolean
}
/** A Change as the review lists it. The path is relative to the Folder, with `/`. Counts are 0 for a binary file. */
export interface Change {
  path: string
  kind: 'added' | 'modified' | 'deleted'
  added: number
  removed: number
  binary: boolean
  byClaude: boolean
}
export type ReviewState =
  | { kind: 'no-git'; message: string }
  | { kind: 'waiting'; message: string }
  | { kind: 'changes'; range: ReviewRange; changes: Change[] }
export type FileDiff = { kind: 'text'; patch: string; byClaude: boolean } | { kind: 'binary' } | { kind: 'none' }
```

### Task 1: Snapshot the Folder without touching the repository

**Files:**
- Create: `src/main/review/git.ts`
- Modify: `src/shared/api.ts` (the shared types above)
- Test: `src/main/review/git.test.ts`

**Interfaces:**
- Produces: `type GitChange = Omit<Change, 'byClaude'>` and `type GitProblem = 'no-git' | 'not-a-repo'`.
- Produces: `parseChanges(nameStatus: string, numstat: string): GitChange[]`. It takes the `-z` outputs. Status `A` is added, `D` is deleted, and `M` or `T` is modified. A numstat of `-` `-` means `binary: true` with counts 0. The order is the name-status order.
- Produces: `class SnapshotStore` with:
  - `static open(folder: string, storeDir: string, git = 'git'): Promise<SnapshotStore | { problem: GitProblem }>`. A `git` that cannot be spawned gives `no-git`. A failing `rev-parse` gives `not-a-repo`. On success it empties `storeDir` and creates `storeDir/objects`;
  - `snapshot(): Promise<string>`, which returns the tree id. Snapshots run one at a time, in call order;
  - `get busy(): boolean`, true while a snapshot runs;
  - `changes(base: string, now: string): Promise<GitChange[]>`;
  - `diff(base: string, now: string, path: string): Promise<string>`.
- Produces: `createReviewDir(base: string): { dir: string; remove(): void }`.
  - It makes `<base>/review-<process.pid>-XXXXXX` with mode `0700`.
  - First it removes each `review-<pid>-*` sibling whose pid is not running. `process.kill(pid, 0)` throws `ESRCH` for those.
  - `remove()` is safe to call twice.

### Task 4: Keep each session's review

**Files:**
- Create: `src/main/review/service.ts`
- Test: `src/main/review/service.test.ts`

**Interfaces:**
- Consumes: `SnapshotStore`, `GitChange` (Task 1); `isClaudeCodesOwnPrompt`, `pathInFolder`, `TouchLog` (Task 2); `HookInput` (Task 3).
- Produces: `class ReviewService` with:
  - `constructor(runDir: string, send: (state: ReviewState) => void, opts?: { pollMs?: number; git?: string })`. `pollMs` defaults to 2000;
  - `setFolder(folder: string | null): Promise<void>`. It opens the store at `<runDir>/<first 16 hex of sha256(folder)>` and never rejects;
  - `startSession(tabId: string, startKey: string): Promise<void>`. It waits for any open in progress, then takes the session base. The newest start is the one shown, and a tab's new start replaces its old one;
  - `hook(startKey: string, e: HookInput): Promise<void>`;
  - `setView(view: ReviewView): void`. It starts or stops the poll, refreshes, and always sends the current state;
  - `refresh(): Promise<void>`;
  - `diff(path: string): Promise<FileDiff>`;
  - `close(): void`, which stops the poll.
- `hook()` resolves once Claude Code may go on, and never rejects:
  - a Developer `UserPromptSubmit`: after the turn base is written and `startTurn()` has run. A prompt from `isClaudeCodesOwnPrompt` resolves at once and changes nothing;
  - `PreToolUse` for `Bash`: after the snapshot before the command is stored under `tool_use_id`;
  - any other event, or an unknown start key: at once. The rest happens in the background:
    - `PostToolUse` for `Write`, `Edit` or `NotebookEdit` touches `pathInFolder(folder, file_path)`;
    - `PostToolUse` for `Bash` takes the snapshot after the command and touches every path in `changes(before, after)`;
    - every `PostToolUse` and `Stop` refreshes.
- `refresh()` skips while `busy`. Otherwise it takes a snapshot, keeps its tree as the latest, and builds the state:
  - Git problems give `no-git` with the Global Constraints' message;
  - no start gives `waiting`, "once Claude starts";
  - `turn` with no turn base gives `waiting`, "no prompt yet";
  - otherwise `changes`, with `byClaude = touches.touched(path, range)`.

  It calls `send` only when the state differs from the last one sent.
- `diff(path)` compares the range's base with the latest tree:
  - a path not in the latest list gives `{ kind: 'none' }`;
  - a binary Change gives `{ kind: 'binary' }`;
  - otherwise `{ kind: 'text', patch, byClaude }`.

### Task 7: Show the difference with revision clouds

**Files:**
- Create: `src/renderer/src/review/{diff.ts,cloud.ts,highlight.ts,DifferencePanel.tsx}`
- Modify: `src/renderer/src/workspace/Workspace.tsx`, `src/renderer/src/workspace/dockview.css`, `package.json`, `pnpm-lock.yaml`, `tests/shots/shots.spec.ts`
- Test: `src/renderer/src/review/{diff.test.ts,cloud.test.ts,highlight.test.ts}`, `tests/e2e/review.spec.ts`, `tests/e2e/look.spec.ts`

**Interfaces:**
- Consumes: `useReview` (Task 6); `reviewDiff` (Task 5).
- Produces: `parsePatch(patch: string): DiffRow[]`, with `interface DiffRow { kind: 'hunk' | 'context' | 'add' | 'del'; oldLine: number | null; newLine: number | null; text: string; block: number | null }`.
  - Lines before the first `@@` are skipped, and so is `\ No newline at end of file`.
  - Line numbers count from the hunk header.
  - Each unbroken run of `add` and `del` rows is one change block, numbered from 0. Other rows have `block: null`.
- Produces: `cloudPath(w: number, h: number, pad: number): string`, ported from `cloudPath` in `~/Workspace/blueprint-prototype/src/looks/looks.js`:
  - `nx = max(2, round(w / 13))` and `ny = max(1, round(h / 13))`;
  - arcs of radius `max(w / nx, h / ny) * 0.62`, clockwise from `M<pad> <pad>`, closed with ` Z`.
- Produces: `highlightLines(path: string, lines: string[]): Promise<{ text: string; color?: string }[][] | null>`.
  - It uses `createHighlighterCore` with `createJavaScriptRegexEngine` and a CSS-variables theme whose variables start with `--bp-code-`.
  - Each language loads the first time it is needed: `typescript`, `tsx`, `javascript`, `jsx`, `json`, `css`, `html`, `markdown`, `shellscript`, `python`, `yaml`, `toml`, `rust` and `go`, chosen by file extension.
  - An unknown extension gives `null`.
  - It highlights the lines in order as one block. A construct that a hunk cuts in half may colour wrong.
- Produces: `DifferencePanel` (component `difference`, root `data-tab="difference"`).
  - With nothing picked it shows `Pick a change to see its difference.`
  - Otherwise it calls `reviewDiff(picked)`, and calls it again on every review update. `binary` shows `Binary file.`, and `none` goes back to the empty message.
  - `text` shows the path in `.bp-diff-path`, then one `.bp-diff-row[data-kind]` per row with the old and new line numbers, the sign and the highlighted text.
  - Each change block is wrapped in `.bp-chg`. When `byClaude`, the block holds an `svg.bp-cloud` with a `path` drawn by `cloudPath`, using an 8 px pad and a 4 px inset, and redrawn by a `ResizeObserver`.
  - `--bp-code-*` maps onto the tokens in `dockview.css`.
