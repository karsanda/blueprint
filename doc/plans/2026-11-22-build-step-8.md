# Build step 8: Presets, keys, floating and pop-out — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Developer rearranges the window with one of four presets, works the panes from the keyboard, and floats a pane or pops it out into its own window.

**Architecture:**
- **Renderer:**
  - `presets.ts` builds a preset's dockview JSON from the open tabs, as a pure function. `applyPreset` loads it with `fromJSON(…, { reuseExistingPanels: true })`.
  - `terminal/keys.ts` gains the workspace key table. `workspace/commands.ts` runs each action, and puts a capture-phase `keydown` listener on every Blueprint window.
  - A Layout menu in the top bar, and a `⋯` menu in each pane's header (Float, Pop out, Dock).
- **Main:**
  - The renderer is served from `blueprint://app/`, because dockview refuses pop-outs from a `file:` page.
  - Only the pop-out page may open as a new window, and pop-out windows refuse navigation like the main window.

**Tech Stack:** As in build step 7 (Electron 45.4.1, electron-vite 6.0.0, React 19, TypeScript 7, dockview-react 8.9.1, @base-ui/react 1.9.0, zustand 5, Vitest 5, @playwright/test 1.65). No new dependencies.

## Global Constraints

- Linux first. Dev and test runs start Electron with `--no-sandbox`. Windows keep `contextIsolation: true`, `sandbox: true` and `nodeIntegration: false`. The renderer reaches main only through `window.blueprint`.
- Presets, with their exact labels, ids and keys:
  - `Agent and review` (`agent-and-review`), Ctrl+Shift+1;
  - `Two agents` (`two-agents`), Ctrl+Shift+2;
  - `Terminal heavy` (`terminal-heavy`), Ctrl+Shift+3;
  - `Focus` (`focus`), Ctrl+Shift+4.

  Their panes, the extra-tab rules and the keyboard rule are as the notes give them.
- The Layout menu:
  - its trigger is a button named `Layout`, at the right end of the top bar;
  - each item reads its label, then its key as `Ctrl+Shift+1` (and so on);
  - it shows only while a Folder is open.
- Keys, matched on `KeyboardEvent.code` with exactly these modifiers held:

  | Code | Ctrl+Shift | Ctrl+Shift+Alt |
  | --- | --- | --- |
  | `KeyH` / `KeyJ` / `KeyK` / `KeyL` | focus left / down / up / right | move the tab left / down / up / right |
  | `KeyT` / `KeyN` | new shell / new Claude session | |
  | `KeyZ` | zoom in or out | |
  | `Digit1`–`Digit4` | preset 1–4 | |

  Ctrl+`Tab` gives the next tab and Ctrl+Shift+`Tab` the previous one. No other key is taken. Ctrl+Shift+C and V stay copy and paste.
- A key is left alone when:
  - it is not a `keydown`;
  - `isComposing` is true;
  - its target is the rename field (`.bp-tab-name`).
- A handled key gets `preventDefault()` and `stopPropagation()` in the capture phase on its window, so it never reaches xterm.
- The pane menu:
  - its trigger is a button named `Pane menu` in each pane's header, just before zoom;
  - its items are `Float` (docked panes), `Pop out` (docked or floating panes) and `Dock` (floating or popped-out panes).
- The pop-out page is `popout.html` in the renderer's public folder: an empty page with a charset and the title `Blueprint`. `addPopoutGroup` gets `popoutUrl: 'popout.html'`.
- The `blueprint` scheme is registered privileged (`standard`, `secure`, `supportFetchAPI`) before `app` is ready. It serves only files inside the built renderer folder, for host `app`. Anything else gets a 404 response.
- The packaged and e2e window loads `blueprint://app/index.html`. A dev run keeps `ELECTRON_RENDERER_URL`.
- The main window's open handler allows exactly the pop-out URL, resolved against the page's own URL. Every other URL is denied; a web URL is opened in the browser first. Each window created that way gets the same `will-navigate` refusal and the same open handler.
- Production code has no test-only branches beyond the existing e2e probe.
- Commit messages follow the repo's style (plain imperative sentence, no `feat:` prefix) and never carry Co-Authored-By or other attribution lines.
- Before finishing, `sh scripts/check_links_integrity.sh` prints only `check-done`, and `pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm e2e` passes.

## Review Focus

1. **A preset with running sessions.** Each Claude tab keeps its program, its name, its saved conversation and its Changes. Nothing restarts, and the review does not end a session. Test: Task 1.
2. **Keys the Developer's programs use.** Ctrl+←, Ctrl+Shift+←, Alt+c and Ctrl+H still reach the shell. Ctrl+Shift+H does not. Test: Task 2.
3. **A floating pane whose neighbour closed.** Dock still puts it somewhere sensible, at the right edge, and never loses it. Test: Task 3.
4. **A pop-out window.** It must not become a way out of Blueprint's page: navigating it or opening a window from it is refused. A path like `blueprint://app/%2e%2e/…` serves nothing outside the renderer folder. Tests: Task 4.
5. **Closing a busy shell that sits in a pop-out.** The question shows in the pop-out window, where the Developer is looking, not behind it in the main window. Test: Task 4.
