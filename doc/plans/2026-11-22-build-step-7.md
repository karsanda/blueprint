# Build step 7: More than one shell — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Developer opens more shells, each in its own tab started in the Folder, renames and closes them, and finds them again when the Folder reopens. Closing a shell that runs a program asks first.

**Architecture:**
- **Main:**
  - `foreground.ts` reads which program holds a terminal's foreground, from `/proc`.
  - `TerminalManager.foreground(tabId)` asks it for a tab's terminal, behind the `terminal:foreground` channel.
- **Renderer:**
  - The Claude tab code in `sessions.ts` takes a tab kind, so numbering, opening and closing work for shells too.
  - `GroupActions` adds a "New shell" action, and `BlueprintTab` lets shell tabs close and take a new name.
  - `requestClose` asks main what a shell runs before it closes it.
  - The layout restore accepts `shell-<n>` tabs.

**Tech Stack:** As in build step 6 (Electron 45.4.1, electron-vite 6.0.0, React 19, TypeScript 7, dockview-react 8.9.1, zustand 5, node-pty 1.1.0, lucide-react 1.77.0, Vitest 5, @playwright/test 1.65). No new dependencies.

## Global Constraints

- Linux first. Dev and test runs start Electron with `--no-sandbox`. Windows keep `contextIsolation: true`, `sandbox: true` and `nodeIntegration: false`, and the renderer reaches main only through `window.blueprint`.
- A shell tab's id is `shell-<n>` and its title `Shell <n>`. The first, `shell-1`, is titled `Shell`. `n` is one past the highest open shell number and every shell number used earlier in the run. Claude numbering is unchanged and counts apart.
- Every group that holds a shell tab has a header action:
  - its `aria-label` and `title` are `New shell`;
  - its icon is Lucide's `SquareTerminal` at size 13, stroke width 1.75;
  - its classes are those of Claude's `+`.

  The actions read, left to right: New shell, New Claude session, zoom. A new shell tab joins that group, active, with the keyboard in its terminal.
- Double-clicking a shell tab's title renames it, as for a Claude tab. The field's `aria-label` is `Shell name`; a Claude tab's stays `Session name`.
- A shell tab has a close action (button and middle-click) while another shell tab is open. The last open shell tab has none.
- When the Developer closes a shell tab:
  - a shell whose terminal status is `exited` or `failed` closes at once;
  - otherwise the renderer asks main for the tab's foreground program, and closes at once when there is none;
  - a busy shell gets Blueprint's close dialog: title `Close <tab title>?`, text `It is still running <program>.`, buttons `Keep it` and `Close shell`.
  - The Claude dialog's copy is unchanged.
- A terminal's foreground program is read as follows:
  - its foreground process group is field 8 (`tpgid`) of `/proc/<shell pid>/stat`, counted after the last `)`;
  - when `tpgid` is the shell's pid, or 0 or less, there is none;
  - otherwise it is `/proc/<tpgid>/comm`, trimmed;
  - any read that fails gives none.
- Closing a shell ends its terminal through the existing `stopTerminal`.
- A saved layout may hold `shell-<n>` tabs, each `component: 'terminal'` with `params.kind: 'shell'`. A `shell-<n>` panel of any other kind makes the layout foreign, which gives the default layout. A layout with no shell tab gets `shell-1` below its first Claude tab. Every restored shell tab starts a fresh shell in the Folder, under its saved title.
- Shell tabs never carry a `conversation` parameter.
- Production code has no test-only branches beyond the existing e2e probe.
- Commit messages follow the repo's style (plain imperative sentence, no `feat:` prefix) and never carry Co-Authored-By or other attribution lines.
- Before finishing, `sh scripts/check_links_integrity.sh` prints only `check-done`, and `pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm e2e` passes.

## Review Focus

1. **A dev server or an editor in a shell the Developer closes.** Blueprint asks first. After `Close shell`, nothing of it keeps running. Test: Task 3, the slice test.
2. **The first shell closed, then the Folder reopened.** The layout stays and `shell-1` never comes back. The next new shell counts on past the highest number. Test: Task 3.
3. **A shell dragged into another pane, such as Claude's.** That pane shows both actions, and each opens its own kind there. Test: Task 2.
4. **A shell that exited, or whose foreground cannot be read.** It closes at once, never behind a dialog or an error. Tests: Task 1 (unreadable) and Task 3 (exited).
5. **A hand-edited layout whose `shell-2` is a Claude terminal.** It gives the default layout, never a Claude program under a shell's name. Test: Task 2.

### Task 1: Tell what a shell runs in its foreground

**Files:**

**Interfaces:**
- Produces: `foregroundProgram(pid: number, read?: (path: string) => string): string | null`. It follows the foreground rules in Global Constraints. `read` defaults to `readFileSync(path, 'utf8')`; it is the only I/O.
- Produces: `TerminalManager.foreground(tabId: string): string | null`. It gives `foregroundProgram(term.pid)` for the tab's current terminal, and `null` when the tab has none.
- Produces: `BlueprintApi.foregroundProgram(tabId: string): Promise<string | null>` on the `terminal:foreground` channel (`ipcMain.handle`, `ipcRenderer.invoke`). Its doc comment says: the program a tab's terminal runs in its foreground, or null when its shell sits at the prompt, has ended or cannot be read.

- [ ] **Step 1: Write the failing tests.**

    - `'a shell at its prompt runs nothing in its foreground'`: `/proc/100/stat` is `'100 (zsh) S 1 100 100 34816 100 4194560'`, so the result is `null`;
    - `'a program in the foreground is named'`: the same stat with field 8 set to `205`, and `/proc/205/comm` as `'vim\n'`, gives `'vim'`;

    - write `'\x03'`, and `waitFor` `manager.foreground('t') === null`;
    - `manager.foreground('none')` is `null`.

### Task 3: Close a shell, asking first while a program runs in it

**Files:**
- Modify: `src/renderer/src/workspace/{sessions.ts,CloseDialog.tsx,Workspace.tsx}`, `tests/e2e/launch.ts`, `tests/e2e/shells.spec.ts`

**Interfaces:**
- Consumes: `BlueprintApi.foregroundProgram` (Task 1); `tabKind`, `isShellTab` and `openTab` (Task 2).
- Produces: `closeTab(api: DockviewApi, tabId: string): void`, replacing `closeClaudeSession`.
  - It does nothing for a tab that is not a terminal tab, or is the last open tab of its kind.
  - It notes the number as used, removes the panel, and disposes the session.
  - It calls `stopTerminal` and clears the terminal status; for a Claude tab it also clears the Claude status.
  - When the closed tab was active, the terminal tab that takes its place gets the keyboard.
- Produces: `requestClose(api: DockviewApi, tabId: string): void`.
  - A Claude tab behaves as today.
  - A shell tab follows the close rules in Global Constraints. The dialog's state says which kind it asks about, so its text and confirm button come from that.
- Produces: `BlueprintTab` gives a terminal tab its close action while another tab of its kind is open.
- Produces: `LaunchOptions.shell?: string`, the `SHELL` a launch uses; it defaults to the fake shell.

- [ ] **Step 1: Write the failing e2e tests** in `tests/e2e/shells.spec.ts`:
  - `'closing a shell that runs a program asks first'` (the slice test):
    - launch with `{ shell: '/bin/sh' }`, open Shell 2, wait for `$` in its probe text, and type `sleep 3071\r`;

    - close it: no dialog shows, and the tab is gone.
  - `'the last shell has no close action'`:

  - `'a closed shell number is not given to the next shell'`: open Shell 2, close it, open another; it is `Shell 3`, and `shell-3` shows `fake-shell ready`.
  - `'closing the first shell keeps the saved layout'`:

    - `Shell 2` shows with `fake-shell ready`, no tab is titled exactly `Shell`, and `[data-tab="shell-1"]` is not attached;
