# Build step 6: Resume after reopening — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reopening Blueprint on a Folder continues each Claude tab's conversation. A conversation that can no longer be found starts fresh, with a notice instead of an error.

**Architecture:**
- **Main:**
  - `resume.ts` decides whether a saved conversation may be resumed, and `claudeSpec` builds either `--resume` or `--session-id` arguments.
  - `startTerminal` resumes a tab's first start from the conversation the renderer sends.
  - The status relay reports each session id's first prompt, and main pushes `claude:conversation` (tab, conversation or `null`) to the renderer.
- **Renderer:**
  - A Claude tab's dockview panel parameters hold `conversation`. An installer copies main's pushes into them, and the layout save writes them like the tab's name.
  - A tab's first start sends the saved conversation, and the terminal notice shows a line when it could not be resumed.

**Tech Stack:** As in build step 5 (Electron 45.4.1, electron-vite 6.0.0, React 19, TypeScript 7, dockview-react 8.9.1, zustand 5, Vitest 5, @playwright/test 1.65). No new dependencies.

## Global Constraints

- Linux first. Dev and test runs start Electron with `--no-sandbox`. Windows keep `contextIsolation: true`, `sandbox: true` and `nodeIntegration: false`, and the renderer reaches main only through `window.blueprint`.
- A Claude tab saves its conversation as the dockview panel parameter `conversation: { sessionId: string; transcript: string }`. Shell tabs never have one.
- Main resumes only when all of these hold:
  - `sessionId` matches `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`;
  - `transcript` is an absolute path whose file name is `<sessionId>.jsonl`;
  - that file exists.
- A resumed start's arguments are `['--resume', sessionId, '--settings', file]`, with no `--session-id`. Any other Claude start keeps today's `['--session-id', <new uuid>, '--settings', file]`.
- Only a tab's first start in a run may resume. Restart after an exit, and a tab opened with `+`, start a new conversation.
- After every successful Claude start, main pushes `claude:conversation` with the resumed conversation, or `null` for a new one. The first `UserPromptSubmit` of each session id a start sees pushes `{ sessionId: session_id, transcript: transcript_path }`.
- When a start asked to resume and could not, the pane shows a notice:
  - it has `role="status"`;
  - its text is `The last conversation could not be found, so a new one started.`;
  - it has a button `Dismiss`.

  The notice goes on Dismiss or at the tab's next start. Claude Code is not stopped or restarted for it.
- The review is unchanged: This session starts over at reopen (the notes record this as a known gap).
- Production code has no test-only branches beyond the existing e2e probe.
- Commit messages follow the repo's style (plain imperative sentence, no `feat:` prefix) and never carry Co-Authored-By or other attribution lines.
- Before finishing, `sh scripts/check_links_integrity.sh` prints only `check-done`, and `pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm e2e` passes.

## Review Focus

1. **A conversation whose history is gone,** for example a deleted transcript. The tab starts a new conversation and shows the notice; it never shows "exited" or an error. Test: Task 3.
2. **A layout file edited by hand,** whose `sessionId` is option-like (`--dangerously-skip-permissions`) or not a UUID. It never reaches Claude Code's arguments, and the tab starts fresh with the notice. Tests: Task 1 and Task 3.
3. **Two sessions reopened.** Each resumes its own conversation, never the other's. A `+` tab opened after reopening starts fresh. Test: Task 3.
4. **Restart after an exit, then quit before any prompt.** Reopening starts fresh, not the conversation from before the restart, and shows no notice. Test: Task 3.
5. **`/clear`, a prompt, then quit.** Reopening resumes the conversation after `/clear`. Tests: Task 2 and Task 3.

### Task 3: Save each tab's conversation and resume it on reopen

**Interfaces:**
- Consumes: `BlueprintApi.onConversation`, `StartRequest.resume`, `StartResult.resumed` (Task 2).
- Produces: `TerminalParams` gains `conversation?: SavedConversation`.
- Produces: `installConversationSaving(api: DockviewApi): () => void`. On each push, it finds the panel by tab id; a missing panel is ignored. It calls `panel.api.updateParameters({ conversation })`, passing `undefined` for `null`. dockview deletes a key set to `undefined`, and a parameter change fires `onDidLayoutChange`, so the layout save writes it. `Workspace` installs it in `onReady` before `restoreLayout` and `addDefaultPanels`, so no push can arrive unheard.
- Produces: `getSession(tabId: string, kind: TerminalKind, resume?: SavedConversation): TerminalSession`.
  - `resume` is used only when the session is created, and only its first `start()` sends it.
  - `restart()` never sends it.
  - `TerminalPanel` passes `params.conversation`.
- Produces: `TerminalStatus` gains `notice?: 'conversation-lost'`.
  - `start()` sets it, with `state: 'running'`, when it sent `resume` and the result has `resumed: false`.
  - `TerminalNotice` shows the notice from Global Constraints for a running tab with that notice. Dismiss sets the status back to `{ state: 'running' }`.
- Produces: in the fake `claude`:
  - its session id is `--session-id`, or else `--resume`;
  - its transcript is `join(log, `${sessionId}.jsonl`)`, and becomes the new id's file after the `c` key;
  - the `p` key appends a line to the transcript before it posts;
  - after `claude ready` it prints `resumed <sessionId>` when started with `--resume`;
  - it appends each session id it takes, at start and at `c`, to `<name>.sessions`.

  The `clear` line in `<name>.hooks` stays as it is: `review.spec.ts` checks it exactly.
