# Build step 2: Know when Claude needs me — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Claude session shows whether it is Idle, Working or Needs you, on its tab, its pane and the title bar. A desktop notification fires when it needs the Developer and the window is not in front, and a click on it brings that session forward.

**Architecture:** Status comes from three sources: Claude Code's HTTP hooks, the keys the Developer types, and the session's transcript.
- The main process runs a private hook listener on `127.0.0.1`. It hands each Claude session a `--settings` file that points the hooks at the listener. It also follows each session's transcript for interrupt lines.
- Main turns what it hears into `StatusSignal`s per tab and sends them to the renderer.
- The renderer folds signals and typed keys into a status per tab with one pure function, `nextStatus`. It draws the marks and asks main to notify on each change to Needs you.
- Main shows the notification only when the window is not focused. A click focuses the window and sends the tab back to the renderer to focus.

**Tech Stack:** As in build step 1 (Electron 45.4.1, electron-vite 6.0.0, React 19, TypeScript 7, Tailwind CSS 4.3, dockview-react 8.9.1, @xterm/xterm 6.0.0, node-pty 1.1.0, zustand 5, Vitest 5, @playwright/test 1.65). New: Node's `node:http` for the listener, and Electron's `Notification`. No new dependencies.

## Global Constraints

- Linux first. Dev and test runs start Electron with `--no-sandbox`.
- Windows keep `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`. The renderer reaches main only through `window.blueprint`.
- Claude Code is the real `claude` CLI, and 2.1.330 is the reference version. Blueprint adds its hooks with `--settings <file>` and never edits the Developer's own settings.
- Hooks are HTTP hooks (`"type": "http"`) for `UserPromptSubmit`, `PermissionRequest`, `PostToolUse`, `Notification` and `Stop`, each with `timeout: 2`. There is no `SessionStart` hook, because Claude Code skips HTTP hooks for it.
- The listener binds `127.0.0.1` only, on a random port. Every request must carry `Authorization: Bearer <token>`, where the token is 24 random bytes in hex. The listener answers `204` with no body, so it never answers a prompt for the Developer.
- The settings file is written with mode `0600` inside a fresh `0700` temp dir, and Blueprint removes that dir on quit.
- UI copy uses the glossary's words. Status labels: `Needs you`, `Working`, `Idle`.
- Window title formats:
  - nothing waits: `Blueprint`;
  - one session: `Needs you: Claude — Blueprint`;
  - several: `Needs you: Claude, Claude 2 — Blueprint`.
- Notification copy: title `Needs you: <tab title>`, body `Claude Code is waiting for your answer in <Folder name>.`
- Status colors come from the tokens: Needs you `--bp-wait` (`#ffa24c`, `rgb(255, 162, 76)`), Working `--bp-agent` (`#ffd166`), Idle `--bp-muted`.
- Production code has no test-only branches beyond the existing e2e probe. Tests stub Electron APIs through `app.evaluate`, as `tests/e2e/window.spec.ts` stubs `shell.openExternal`.
- Commit messages follow the repo's style (plain imperative sentence, no `feat:` prefix) and never carry Co-Authored-By or other attribution lines.
- Before finishing, `sh scripts/check_links_integrity.sh` prints only `check-done`, and `pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm e2e` passes.

## Review Focus

1. A session needs the Developer while its pane is hidden behind a zoomed pane. Clicking the notification should leave the zoom and show that session. Test: Task 7, the click test zooms the shell pane first.
2. The Developer clicks into a pane that shows Needs you, so the terminal sends a focus report. Needs you must stay, because only typed keys count. Test: Task 5, the fake `claude` turns on focus reporting.
3. A Claude session exits or restarts while it shows Needs you. The mark goes with the exit, the new session starts Idle, and events from the old session change nothing. Tests: Task 4 (`StatusRelay`) and Task 5 (restart).
4. Something other than Blueprint's sessions posts to the listener: another local program, a request without the token, broken JSON or a very large body. Blueprint ignores it and keeps serving. Test: Task 1, listener tests.
5. The settings file carries the listener's token. Only the Developer can read it, and it is gone after quit. Test: Task 4.

Shared types, defined in Task 1 and used everywhere after:

```ts
// src/shared/api.ts
export type ClaudeStatus = 'idle' | 'working' | 'needs-you'
/** What Blueprint learned about a Claude session. The renderer folds it into a ClaudeStatus. */
export type StatusSignal =
  | { kind: 'prompt' } // UserPromptSubmit
  | { kind: 'asks' } // PermissionRequest, or Notification permission_prompt / elicitation_dialog
  | { kind: 'tool-done' } // PostToolUse
  | { kind: 'stop' } // Stop
  | { kind: 'interrupted' } // the transcript gained an interrupt line
  | { kind: 'typed' } // the Developer typed a key in the pane (renderer only)
```

### Task 1: Hear Claude Code's hooks on a private listener

**Files:**

**Interfaces:**
- Produces: `interface HookInput { hook_event_name: string; session_id: string; transcript_path?: string; notification_type?: string }`. Other fields are ignored.
- Produces: `HOOK_EVENTS = ['UserPromptSubmit', 'PermissionRequest', 'PostToolUse', 'Notification', 'Stop'] as const` and `type HookEvent = (typeof HOOK_EVENTS)[number]`.
- Produces: `hookSettings(url: string, token: string): { hooks: Record<HookEvent, HookMatcher[]> }`, one matcher per event.
  - Each matcher is `{ hooks: [{ type: 'http', url, headers: { Authorization: 'Bearer ' + token }, timeout: 2 }] }`.
  - `PermissionRequest` and `PostToolUse` also get `matcher: '*'`.
- Produces: `writeHookSettings(settings: object): { file: string; remove(): void }`. It makes a dir with `mkdtempSync(join(tmpdir(), 'blueprint-hooks-'))` and writes `settings.json` there with mode `0o600`. `remove()` deletes the dir and is safe to call twice.
- Produces: `signalFromHook(e: HookInput): StatusSignal | null`, following the notes' table.
- Produces: `startHookListener(onEvent: (e: HookInput) => void): Promise<HookListener>`, with `interface HookListener { url: string; token: string; close(): Promise<void> }`. `url` is `http://127.0.0.1:<port>/hook`.
  - `POST /hook` with the exact bearer token: read the body, answer `204` with no body, then parse. A JSON object with string `hook_event_name` and `session_id` goes to `onEvent`. Anything else is dropped.
  - A wrong or missing token gets `403`. Another path or method gets `404`.
  - A body over 32 MiB gets `413` and is not read further.

### Task 2: Notice when the Developer interrupts Claude Code

**Files:**
- Create: `src/main/status/transcript.ts`
- Test: `src/main/status/transcript.test.ts`

**Interfaces:**
- Produces: `isInterruptLine(line: string): boolean`. True when the line parses to an object with `type === 'user'` and an array `message.content` that has a part with `type === 'text'` and a `text` starting with `[Request interrupted by user`. False for anything else, including broken JSON.
- Produces: `class TranscriptFollower` with:
  - `constructor(onInterrupt: (sessionId: string) => void, intervalMs = 300)`;
  - `follow(sessionId: string, file: string): void`;
  - `unfollow(sessionId: string): void`;
  - `unfollowAll(): void`.

  `follow` does nothing if it already follows that session. Otherwise it records the file's current size (0 when the file is missing) and watches it with `fs.watchFile(file, { interval: intervalMs })`. On growth, it reads the new bytes, keeps a trailing partial line for the next read, and calls `onInterrupt` for each complete interrupt line. If the file shrinks, it starts over from 0.

- Produces: in `index.ts`, the order is:
  1. create the relay;
  2. `await startHookListener((e) => relay.hook(e))`;
  3. `writeHookSettings(hookSettings(url, token))`;
  4. then create the window and register IPC, so every handler exists before the renderer loads.

  The relay sends on channel `status:signal` (`tabId, signal`). On `window-all-closed` and `before-quit`, call `listener.close()`, `relay.close()` and `settings.remove()`. Both events fire on quit, so this cleanup runs once.

  A post sends `{ session_id, transcript_path, cwd, hook_event_name, ...extra }` to the URL and headers found at `hooks[event][0].hooks[0]` in the settings file. Posts run one at a time, in order. Each appends `<event> <status>\n` to `<log>/claude.hooks`.
