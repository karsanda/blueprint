The first release of Blueprint: the MVP, for Ubuntu and macOS. Blueprint puts Claude Code, your shells and a review of what Claude changed in one window, in a drafting-table look.

## What it does

- **Talk to Claude in a pane:** the real `claude` CLI in a tab, signed in with your own account. Each Claude tab resumes its conversation when the Folder reopens.
- **Run commands in a shell pane:** your own shell, in the Folder, as many as you like.
- **Arrange my panes:**
  - tiled panes and tabs, with the layout and window remembered per Folder;
  - four presets (Ctrl+Shift+1 to 4) and keyboard control (Ctrl+Shift+H/J/K/L);
  - floating panes, and pop-out windows.
- **Know when Claude needs me:** a status light per session, the window title, and a desktop notification when Claude Code waits for you.
- **Review what Claude changed:** Changes for this turn or this session, each Change credited to the session that made it, and its Difference beside.
- **Run several Claude sessions:** side by side, renamed, closed, with a warning when two of them change the same file.

## Install

Blueprint needs [Claude Code](https://docs.anthropic.com/en/docs/claude-code), installed and signed in.

**Ubuntu** (amd64): download `blueprint_0.1.0_amd64.deb`, then:

```sh
sudo apt install ./blueprint_0.1.0_amd64.deb
blueprint ~/path/to/project
```

It also adds Blueprint to the app menu, which opens a folder picker.

If apt ends with "Download is performed unsandboxed as root", the install still worked. apt's own user can't read your home folder, so apt read the file as root.

**macOS** (Apple Silicon):
1. Open `Blueprint-0.1.0-arm64.dmg` and drag Blueprint into Applications.
2. The app is not signed with a Developer ID, so allow its first open: open it once, then choose Open Anyway in System Settings › Privacy & Security. Or run `xattr -dr com.apple.quarantine /Applications/Blueprint.app`.
3. For the `blueprint` command, link it once into a folder on your `PATH`:

   ```sh
   mkdir -p ~/.local/bin
   ln -s /Applications/Blueprint.app/Contents/Resources/bin/blueprint ~/.local/bin/blueprint
   blueprint ~/path/to/project
   ```

   A stock Mac has no `~/.local/bin` on its `PATH`. Add `export PATH="$HOME/.local/bin:$PATH"` to `~/.zprofile`, or link into `/usr/local/bin` with `sudo` instead.

On both, `blueprint <folder>` gives the prompt back at once, and each Folder opens in its own window.

## Keys

| Keys | What they do |
| --- | --- |
| Ctrl+Shift+C / Ctrl+Shift+V (and Cmd+C / Cmd+V on macOS) | copy and paste in a terminal |
| Ctrl+Shift+H / J / K / L | move the keyboard to the pane on the left / below / above / right |
| Ctrl+Shift+Alt+H / J / K / L | move the tab to that pane |
| Ctrl+Tab / Ctrl+Shift+Tab | next / previous tab |
| Ctrl+Shift+T / Ctrl+Shift+N | new shell / new Claude session |
| Ctrl+Shift+Z | zoom the pane |
| Ctrl+Shift+1 to 4 | Agent and review, Two agents, Terminal heavy, Focus |

On macOS, Option acts as Alt in terminals.

## Known gaps

- **Not checked by hand on a Mac yet:**
  - the first open after Gatekeeper;
  - desktop notifications (#18, #44);
  - Claude Code finding your tools when Blueprint is opened from Finder.

  Both test suites pass on macOS in CI.
- A popped-out terminal may pause while the main window is minimized.
- The review keeps its records only while Blueprint runs: after a reopen, This session starts over (#27).
- Two windows on one Folder resume the same conversations (#29).
